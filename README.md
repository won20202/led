# LED 플래카드 설계 시뮬레이터

중학교 2학년 기술·가정 「제조 기술 문제해결」 수행평가 보조 웹앱.
**결과는 보여주되, 답은 주지 않는다** — 학생이 정한 값의 결과만 보여주고, 계산·판단은 학생 몫으로 남깁니다.

## 구성

| 탭 | 내용 |
|---|---|
| 케이스 | 조각 치수 입력 → 3D 조립. 두께 미반영 시 겹침(빨강)·틈(노랑)이 그대로 보임. 예측 먼저 입력해야 조립 가능. 펼치기/접기, 단면 보기, 재단 배치 뷰, 설계 일지 |
| 회로 | 설치할 면을 골라(뒷면 안쪽 / 옆면 둘레 띠) 테이프·LED·홀더 배치. 띠의 양 끝은 조립하면 만나는 것으로 계산(순환 연결). 부품은 면 밖으로 나가지 않음. 병렬=밝게, 직렬 2개=눈에 띄게 어둡게, 직렬 과다=자동 소등. 합선/끊김/극성/스위치 방향, 전선을 LED 다리에 직접 연결해도 점등. 저항 없이 점등하면 LED 수명 경고, 관리자가 켜면 저항 부품 사용 가능. 휠/버튼으로 확대 |
| 도안 | 검은 앞면에 글자 2개 + 그림판식 자유 그리기. 떨어져 나가는 안쪽 조각 빨간 표시, 잘라낼 둘레 길이(cm), 조건 위반 경고 |
| 조립 순서 | 작업 카드 배열 → 실행. 순서가 틀리면 그 결과가 나옴 (정답 미제공) |
| 미리보기 | 케이스+회로+도안을 합친 완성본 — 어느 위치에 어떤 색 빛이 나오는지. 홀더 위치가 나쁘면 넘어짐 |
| 도움말 | AI 아님. 평가 기준(배점표) 열람 + 교사가 편집하는 FAQ + 검색. 못 찾은 검색어는 수집되어 관리자에게 보임 |

회로 밝기 모델은 교육용 근사입니다(직렬이 많아질수록 어두워지다 꺼지도록 문턱 전압 1.2V·내부 저항 90Ω 기본값). 실제 백색 LED처럼 "직렬 2개=즉시 소등"으로 쓰려면 관리자 설정에서 문턱 전압을 3.0으로 바꾸면 됩니다.

## 학생 사용

1. 주소 접속 → **반·번호 선택**(이름 없음) → 시작
2. 반 코드를 설정한 경우 코드 입력 필요
3. 작업은 자동 저장(기기 localStorage + 설정 시 서버)

## 관리자(교사) 모드

- 로그인 화면 아래 [관리자] 버튼, 또는 주소 뒤 `?admin=1` → PIN 입력 (**초기 PIN: 2026** — 꼭 바꾸세요)
- 수업 설정: 우드락 두께, LED 개수, 저항 사용 여부, 회로 모델(문턱 전압·내부 저항), 치수·표시 항목·예측 먼저 등
- 평가 기준(배점표) 편집: 영역 수·조건 설명·수준별 배점을 해마다 자유롭게 수정 — 학생에게는 도움말의 [평가 기준 보기]로 표시
- 학생 작업 열람: Supabase 설정 시 반 전체 목록이 20초마다 자동 갱신, [보기]로 열면 15초마다 실시간 갱신되는 읽기 전용 화면
- FAQ 편집, 못 찾은 검색어 확인
- **설정 코드**: [내보내기] → 코드 복사 → 다른 크롬북에서 붙여넣고 [불러오기]
  (Supabase를 쓰면 설정 코드에 키가 포함되므로 학생에게 노출하지 말 것)

## 배포 (권장: GitHub Pages)

이 폴더 전체가 정적 사이트입니다. 빌드 불필요.

1. GitHub에 새 저장소 만들기 (예: `led-placard-sim`)
2. 이 폴더 push
3. 저장소 Settings → Pages → Branch `main`, 폴더 `/ (root)` 선택
4. 1~2분 뒤 `https://<계정명>.github.io/led-placard-sim/` 접속
5. **학교망에서 크롬북으로 열리는지 사전 확인** (차단 시 Vercel `vercel.app`으로 대체)

Vercel을 쓰려면: vercel.com에서 GitHub 저장소 연결만 하면 끝 (Framework: Other).

## 학생 작업을 한곳에 모으기 (선택: Supabase)

서버 없이도 앱은 완전히 동작합니다(기기별 저장). 반 전체 작업을 교사가 한 화면에서 보려면:

1. supabase.com 가입 → 새 프로젝트 생성 (무료)
2. SQL Editor에 `supabase.sql` 내용 붙여넣고 실행
3. Project Settings → API에서 **Project URL**과 **anon public key** 복사
4. 앱 관리자 모드 → 수업 설정에 URL/key 입력 → 저장 → 설정 코드로 크롬북에 배포
5. 헤더의 점이 초록색이면 서버 저장 중. 서버가 막혀도 자동으로 기기 저장으로 계속됨

비밀번호는 두지 않았습니다. 학번 선택 + (선택) 반 코드면 수업용으로 충분하고,
비밀번호 분실 처리가 수업 시간을 더 잡아먹습니다.

## 학생 활동·피드백을 구글 시트에 기록 (선택)

학생이 무엇을 시도했고 어떤 피드백을 받았는지가 시트에 한 줄씩 쌓입니다
(접속, 설계 일지, 점등 결과, 도안 피드백, 도움말 검색 중 답을 못 찾은 검색어).
다음 수업 개선과 평가 계획 자료로 쓰는 교사용 데이터입니다.

1. 구글 시트 새로 만들기 → 확장 프로그램 → Apps Script
2. 아래 코드를 붙여넣고 저장:

```
function doPost(e) {
  var rows = JSON.parse(e.postData.contents);
  var ss = SpreadsheetApp.getActiveSpreadsheet();
  rows.forEach(function (r) {
    // 반별 탭에 나눠서 기록 (1반, 2반, …). 탭 안에서는 번호로 정렬해 보면 학생별로 보인다.
    var name = (r.ban || r.ban === 0) ? r.ban + '반' : '기타';
    var sh = ss.getSheetByName(name) || ss.insertSheet(name);
    if (sh.getLastRow() === 0) sh.appendRow(['시각', '번호', '학번', '이벤트', '내용']);
    sh.appendRow([new Date(r.ts), r.num || '', r.id, r.event, r.detail]);
  });
  return ContentService.createTextOutput('ok');
}
```

기록되는 이벤트: 접속 · 설계 일지(케이스 조립 시도와 결과) · 회로 점등(예측 포함) ·
도안 피드백 · 도움말 검색 중 답을 못 찾은 검색어 · 교사 메모.
290명(10개 반) 규모도 문제없습니다 — 반 탭 10개에 나눠 쌓이고,
각 탭에서 번호 열로 정렬·필터하면 학생별 기록이 됩니다.
관리자 모드의 [시트 기록 테스트] 버튼으로 연결을 확인할 수 있습니다.

3. 배포 → 새 배포 → 유형: 웹 앱 → 액세스 권한: **모든 사용자** → 배포
4. 나온 웹 앱 URL(`https://script.google.com/macros/s/…/exec`)을
   앱의 관리자 모드 → 수업 설정 → **Google Sheet 기록 URL**에 붙여넣고 저장
5. 설정 코드로 크롬북들에 배포하면 모든 학생 기록이 한 시트에 모입니다

## 개발 메모

- 순수 정적 HTML/JS/CSS + Three.js(로컬 번들, `vendor/`). 빌드 도구 없음
- 모든 경로 상대 경로 → 하위 경로 배포(GitHub Pages) 안전
- 상태: localStorage / 선택적 Supabase REST 동기화 (`js/state.js`)
- 회로 해석: 테이프 연결 성분(union-find) + LED 방향 그래프 경로 탐색 (`js/circuit.js`)
